# 法护通桌面网页端设计说明书

## 1. 文档目标

本文档定义 `frontend/` 的产品范围、信息架构、视觉规范、交互规则与后端对接方式。前端以现有 FastAPI、GuideGraph 和 Gradio 测试台的真实能力为唯一业务依据，不在浏览器端复制或改写案件判断逻辑。

本轮只开发电脑网页端。推荐使用 1440 × 900 或更大的浏览器窗口，最低桌面布局宽度为 760 px；不设计手机端导航、触控专用流程或手机式底部导航。

## 2. 产品定位

法护通是面向普通市民和企业用户的法律咨询与维权辅助工作台，覆盖两类核心任务：

1. 法律知识问答：法条、类案、办事渠道、专业文档和法律统计查询。
2. 具体案件梳理：采集事实和证据，处理安全与时效风险，进行动态追问，生成行动方案及参考文书。

前端不是“通用聊天皮肤”，而是一个自适应桌面案件工作区。宽屏同时显示案件导航、对话和资料检查器；较窄的桌面应用窗口保留案件导航与对话主区，资料检查器通过右侧抽屉打开。两种布局都避免展示内部 Agent 轨迹、Redis 键、数据库地址、会话 ID 或后端地址。

顶部提供两个显式工作模式：

- **法律问答**：独立会话，用于法条、流程、渠道、类案和统计查询，不写入正在处理的维权案件。
- **案件维权**：独立案件状态，用于长期积累事实、证据、进展、方案与参考文书。

## 3. 设计原则

### 3.1 后端能力完整映射

- 使用 `/api/v1/chat/stream` 处理所有自然语言对话与控制消息。
- 使用与 Gradio 完全一致的 `【首次案件材料包】` 文本格式。
- “现在生成方案”“继续补充”“生成文书”保持为控制消息。
- 文档上传后把后端返回的 `evidence_block` 追加到本轮消息。
- 图片上传固定使用 `auto_inject=false`，再把唯一一份视觉证据块追加到本轮消息，避免重复处理。
- 展示后端返回的法条、类案、图谱、统计、文书和官方模板，不在前端补造结论。

### 3.2 结果先于技术

普通用户只看见“会话状态、案件资料、法律检索、文件服务”等能力状态，不显示 PostgreSQL、Redis、Milvus、Neo4j、API 地址或内部标识。检索详情保留在右侧“检索依据”页签，作为可核查来源，而非开发调试面板。

### 3.3 长文本整齐可读

后端返回 Markdown 时按法律方案的阅读习惯排版：

- 法律问答先显示“核心结论”，再按适用规则、办理步骤、注意事项和依据来源分节；不机械凑栏目。
- 案件追问固定显示“已记录 / 请确认 / 为什么要问”，核心问题用引用块突出，一轮只出现一个问题。
- 行动方案保持理解、法律依据、路径比较、胜算评估和行动清单等稳定章节。
- 标题必须单独成行，标题、正文、列表之间保留空行；不把多个要点连写在同一行。
- 二级标题使用左侧色条形成章节锚点。
- 列表保持稳定缩进和行距。
- 引用及注意事项使用暖色提示块。
- 表格允许横向滚动，不挤压正文。
- 链接在新窗口打开，代码和 SQL 使用等宽字体。
- 单个自然段原则上不超过四句话，只加粗影响判断的期限、金额、结论和行动。

### 3.4 证据边界可见

上传的文件或图片不会被前端标为“真实有效”。界面固定说明其属于待核验材料，并展示处理状态。文档解析、图片识别失败时保留明确错误，不能静默丢弃附件。

## 4. 信息架构

```text
顶部栏
├─ 品牌与产品定位
├─ 当前工作区与风险提示
└─ 新建案件

左侧栏
├─ 当前案件概览
├─ 我的案件 / 我的问答
├─ 常见场景入口
├─ 服务能力状态
└─ 隐私提示

中央工作区
├─ 首次案件材料包
├─ 咨询对话
├─ 附件选择与处理状态
├─ 消息输入框
└─ 生成方案 / 继续补充 / 生成文书

右侧检查器
├─ 案情台账
├─ 检索依据与法律统计
└─ 生成文书与官方模板
```

## 5. 核心流程

### 5.1 普通法律问答

用户直接输入法律概念、流程、法条或渠道问题。前端发送原文，由 Supervisor 路由至法律问答 Worker；若返回检索依据，右侧检查器同步更新。

### 5.2 首次案件材料包

材料包允许填写：

- 事情经过
- 对方及双方关系
- 时间、地点和金额
- 希望解决的结果
- 已经沟通或处理的情况

至少填写一项才能提交。空白项不传给后端，且材料包中明确声明“未填写的项目表示本轮未提供，不能推测”。

材料包默认收起，让用户进入页面后优先看到对话入口；需要一次性提供完整案件信息时再展开，不以大表单占据日常问答的首屏。

### 5.3 案件追问与收敛

后端一次只返回一个高价值追问。用户可自然回答，也可使用：

- 现在生成方案：按当前信息立即收敛。
- 继续补充：恢复同一案件的补充流程。
- 生成参考文书：基于当前案件状态请求独立文书服务。

快捷操作不会在前端改写成案情事实。

每轮追问使用固定 Markdown 结构：

```markdown
### 已记录

本轮新增案情摘要。

### 请确认

> **唯一需要回答的问题？**

**回答提示：** 可以如何简短回答。

### 为什么要问

- **用途：** 这个答案会影响的判断。
- **追问依据：** 法律、办理指南或系统整理规则的边界说明。
```

同一段案情不得在开场、问题和依据中重复粘贴；不方便补充时始终保留“现在生成方案”出口。

### 5.4 对话与案件管理

法律问答和案件维权分别维护独立记录列表。每条记录包含匿名 `session_id`、自动生成的标题、更新时间、可见消息和当前检查器状态。

- 点击“新建问答”或“新建案件”生成新的匿名 `session_id`。
- 切换模式时恢复该模式最近一次记录，不覆盖另一模式的状态。
- 点击历史记录可重新打开并继续发送消息。
- 案件状态默认不按时间自动过期，只有用户确认删除后才调用后端删除接口。
- 删除会同时清除浏览器历史、GuideState、Supervisor 检查点、统计上下文、相关临时文书和该案件写入的长期记忆。
- 匿名 `user_id` 保持不变；内部标识不显示在界面。当前实现面向同一浏览器，跨设备同步需后续账号体系。

### 5.5 文件与图片

- 支持 PDF、DOCX、TXT 和常见图片格式。
- 单次前端最多选择 8 个文件；后端仍执行真实大小、格式、页数和像素限制。
- 文档使用 `/upload-document`，采用返回的带指纹证据块。
- 图片使用 `/upload-image`，`auto_inject=false`，前端构造与 Gradio 相同的“视觉模型识别，需与原图核对”证据块。
- 文件处理时显示加载状态；出错时标红并允许用户移除后重试。

### 5.6 法律统计

统计结果展示五个层次：

1. 后端确定性回答。
2. 摘要。
3. 后端推荐的 line、bar、pie、scatter、heatmap 或 table 图表。
4. 原始查询行与字段。
5. 数据集、发布机构、年份、质量标记和已通过安全校验的 SQL。

图表只消费后端数值，不做推算或补值。

### 5.7 文书与官方模板

生成文书后自动切换到“文书模板”页签，提供：

- 短期有效的智能填写 DOCX。
- 精确或相关匹配的官方空白 PDF。
- 官方模板来源、发布机关、文号、生效时间和页码。
- 提交前仍需补充的字段。

下载地址通过前端 API 基础地址解析，但不向用户显示该地址。

## 6. 视觉系统

### 6.1 气质

视觉关键词为“克制、可信、清晰、高效”。界面采用低装饰、低阴影和紧凑层级，避免法院徽章式的权威压迫、营销展示页的大留白，也避免普通 AI 聊天产品的漂浮气泡感。

### 6.2 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 主墨色 | `#17282d` | 标题与高权重正文 |
| 主品牌色 | `#177e89` | 操作、链接、流程状态 |
| 深品牌色 | `#0d6069` | 强调与悬停 |
| 纸张背景 | `#fbfcfa` | 面板背景 |
| 工作区背景 | `#f2f3ef` | 页面底色 |
| 警示暖色 | `#c9603f` | 错误与风险 |
| 依据暖金 | `#b57d24` | 引用、证据边界与注意事项 |

### 6.3 字体

- 界面正文：系统无衬线字体，优先使用苹方、微软雅黑和 Noto Sans CJK SC。
- 品牌、页面标题、法律方案标题：Georgia 与系统宋体组合。
- SQL 与代码：Cascadia Code、Consolas。

### 6.4 布局

- 顶部栏 56 px，底部声明 28 px。
- 1180 px 以上采用 `218 px / 自适应 / 340 px` 三栏。
- 760–1180 px 采用 `168–176 px / 自适应` 双栏，资料检查器以 360 px 右侧抽屉呈现。
- 面板圆角控制在 4–6 px，使用低对比灰绿描边，常驻面板不使用装饰性阴影。
- 首次材料包默认收起，中央对话区是视觉中心；各栏独立滚动，页面主体不整体滚动。

## 7. 状态与异常

| 状态 | 界面行为 |
| --- | --- |
| 首次进入 | 自动检查服务能力、加载官方模板目录 |
| 服务正常 | 绿色状态点和能力标签 |
| 部分能力异常 | 暖橙状态点；对话失败时显示用户可读错误 |
| 正在请求 | 锁定重复发送，显示“正在处理”与加载动画 |
| 附件处理中 | 文件条显示旋转图标 |
| 附件失败 | 文件条标红，保留错误提示与移除入口 |
| SSE 解析失败 | 在对话区显示连接未完成，不显示原始 `data:` 内容 |
| 统计返回 | 自动切换到“检索依据” |
| 文书返回 | 自动切换到“文书模板” |
| 下载过期 | 由后端返回明确错误，用户可重新生成 |

## 8. 无障碍与键盘操作

- 所有图标按钮提供 `title` 或可见标签。
- 交互控件提供可见焦点环。
- Enter 发送，Shift + Enter 换行。
- 页签使用 `role=tablist`、`role=tab` 和 `aria-selected`。
- 动画遵守 `prefers-reduced-motion`。
- 内容颜色保持正文可读对比度。

## 9. 技术实现

- React 18 + TypeScript + Vite。
- `react-markdown` 与 `remark-gfm` 渲染后端 Markdown。
- Recharts 渲染后端推荐的统计图表，热力图由确定性 CSS 网格呈现。
- 匿名 `user_id`、双模式会话目录和可见消息存于浏览器 `localStorage`；后端案件状态与 Supervisor 检查点按 `session_id` 长期保留。
- `GUIDE_SESSION_TTL=0` 表示案件仅手动删除；生成文书继续使用短期下载链接。
- API 地址从 `VITE_API_BASE` 读取，默认 `http://127.0.0.1:8085`。
- 前端只调用公开 HTTP API，不读取 Redis、数据库、Agent 内部状态或 Gradio 组件状态。

## 10. 验收标准

1. Vite 类型检查与生产构建通过。
2. 首次材料包和自然语言消息均可产生整齐的 Markdown 回复。
3. 多轮案件不会出现 `NoneType.session_id`，SSE 只显示公开 Worker 回复。
4. PDF、DOCX、TXT、图片至少各验证一次正常或明确失败路径。
5. 法律知识问答与具体案件均可路由。
6. line、bar、pie、scatter、heatmap、table 均有展示实现。
7. 参考 DOCX 与官方 PDF 下载入口可用。
8. 法律问答与案件维权使用独立会话，切换后可恢复各自记录。
9. 案件在刷新和重新打开浏览器后仍可继续，删除时同步清理前后端状态。
10. Gradio 仍可在 7864 端口独立运行。
11. 界面不显示 API 地址、数据库名、内部用户 ID 或会话 ID。
