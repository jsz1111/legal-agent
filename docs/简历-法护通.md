# 法护通项目简历

## 项目一：法护通 · 公民维权 Agent

```text
项目名称：法护通 - 公民维权 Agent
项目角色：核心开发者
项目时间：2025.10 - 至今

项目介绍：
面向普通市民的维权辅助系统，基于 FastAPI + LangGraph 构建多轮案件状态机，
完成从用户事实描述、场景判断、动态追问、证据评估、知识检索到行动计划生成的闭环。
模型均通过 API 调用，不涉及模型训练或微调。

技术栈：
FastAPI / LangGraph / LangChain / React / PostgreSQL / Redis / Milvus / Neo4j / MinIO / Qwen API
```

负责内容：

```text
1. 多轮维权状态机
   基于 LangGraph 实现案件状态机，将案件拆分为 case、issues、facts、followup、
   evidence、retrieval、control、safety、output 九类结构化状态。
   支持跨轮补充、更正、否认事实，并通过 Redis 持久化会话状态，
   用户可在任意轮次继续补充或要求按当前信息生成方案。

2. 场景再判断与路由门控
   在领域化追问和检索之前，使用完整案情快照重新判断最接近的实际场景。
   低置信度时先让用户用日常语言确认场景，再进入领域化流程；
   高置信度时允许更新法律领域。
   新增低信息消息门控：用户只发“我”“好”“嗯”等消息时，
   不触发长期记忆和领域提取，直接澄清，避免旧记忆或旧领域把空消息误判成网络诈骗。

3. 两阶段动态追问
   先按 13 个法律领域生成固定事实表单，
   再基于决策充分度、检索依据和对抗性缺口扫描动态补充问题。
   支持短文本、长文本、单选、多选，并对已问问题、决策键去重。
   从对方当事人和办案/受理机关视角补充“谁先动手、是否持械、证据是否易消失”等风险缺口。

4. 证据中心
   围绕证明目标维护证据需求、材料持有状态、覆盖评估、替代材料和版本号。
   区分已上传、用户称持有、明确没有、未确认四类状态。
   支持 upload 与 retrieve 两类收集方式，并标记易消失证据。
   只说明材料可能支持什么、缺什么、如何补强，不认定真实性、合法性、可采性或最终证明力。

5. 最终方案生成与校验
   最终方案经过争点识别、争点补充检索、要件分析、策略中枢、反方压力测试、
   用户处境审视和批判修订。
   生成后执行法条白名单、事实接地、证据表述、必需章节等确定性校验，
   保证法条名称、条号和原文来自本轮真实检索上下文。

6. 工程化落地
   完成 React 前端、SSE 进度、动态表单、证据面板、统计图表、
   方案 Word 导出和官方空白模板下载。
   当前全量自动化测试 431 passed，5 subtests passed。
```

## 项目二：法护通 · 法律知识问答 Agent

```text
项目名称：法护通 - 法律知识问答 Agent
项目角色：核心开发者
项目时间：2025.10 - 至今

项目介绍：
面向法律知识查询的 RAG Agent，统一封装法条、类案、知识图谱、渠道、
专业文书和法律统计六类检索能力，并实现查询改写、混合检索、来源校验和审计追踪。
模型均通过 API 调用，不涉及模型训练或微调。

技术栈：
LangChain / FastAPI / Milvus / Neo4j / PostgreSQL / Redis / Qwen API / Plotly
```

负责内容：

```text
1. 六类法律检索工具
   实现 search_statute、search_similar_cases、search_legal_graph、
   search_channels、search_legal_docs、search_legal_statistics 六类工具。
   复杂问题可组合多工具，例如“法条 + 渠道”“统计 + 法条”。

2. 法条 RAG 管线
   实现 Dense + Sparse/RRF 混合检索、HyDE 假设文档增强、Reranker 精排、
   PostgreSQL 字面补充和法律标题补全。
   回答生成后执行幻觉检测，将无法由检索原文支撑的陈述标记出来。

3. 类案与知识图谱检索
   类案检索支持领域过滤、RRF、HyDE、Reranker 和 PostgreSQL 详情补全；
   知识图谱检索通过 LLM 抽取实体、生成 Cypher、执行查询，
   并在失败后把错误反馈给 LLM 修正，最多重试 2 次。

4. 法律统计 ChatBI
   基于《中国法律年鉴》统计库实现 NL2SQL。
   先做确定性目录检索，再让 LLM 生成 SQL，
   经过 schema/表名/危险函数/SELECT 白名单校验后只读执行。
   支持年度趋势、案件占比、指标对比、连续统计追问和图表推荐。

5. 来源接地与审计
   法条回答强制附带检索到的法条原文，前端资料检查器展示法条、类案、
   图谱、渠道和统计来源。
   每次检索记录用户、查询、工具、索引、耗时和结果摘要，便于审计和问题排查。
```

## 两个项目的整体亮点

```text
- 覆盖 13 个法律领域，支持劳动、消费、合同、房产、交通、刑事治安等高频维权场景；
- 法条、类案、图谱、渠道、专业文书、统计六类知识检索统一接入；
- 从“用户事实描述”到“行动计划”形成可校验闭环；
- 最终方案不输出胜诉概率，法条必须来自检索上下文，信息不足时输出条件式方案；
- 全量自动化测试 431 passed，5 subtests passed。
```

## 面试口头版本

“我做的法护通有两个 Agent。公民维权 Agent 是一个多轮状态机，核心是场景判断、
动态追问、证据评估和最终方案校验；法律知识问答 Agent 是一个六类工具的 RAG 系统，
包含法条混合检索、类案、图谱、渠道、文书和法律统计 NL2SQL。
两个 Agent 通过 Supervisor 路由，但模式锁定后各自维护独立状态，避免案件事实与
普通问答相互污染。最终方案强调三件事：缺口被识别、行动可执行、依据可追溯。”
