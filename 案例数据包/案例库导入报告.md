## 2. 数据保存方式

### PostgreSQL

PostgreSQL 保存：

- 稳定 `case_id`
- 原始链接
- 案号、案件名称、案由
- 法院、地区、案件类型、审理程序
- 裁判日期、公开日期、当事人
- 法律依据
- 清洗后全文及全文字数
- `retrieval_text`
- 质量筛选标签

清洗后全文只保存在 PostgreSQL，不直接送入向量模型。

### Milvus

Milvus 只保存和向量化精简后的 `retrieval_text`，长度范围为 443—754 字，平均约 627 字。该文本由案件名称、案由、案件内容、法院说理和裁判结果组成。

数据包中的商业“来源”字段没有导入。为兼容旧表结构，历史 `source` 列仍保留，但本批记录值为空，Agent 回复也不会展示该字段。

## 4. Agent 接入情况

同一个 `case_index` 和 PostgreSQL 案例表同时供两个 Agent 使用：

1. 维权 Agent：在方案生成前检索类案，用于补充裁判倾向、证据重点和成功可能性判断。
2. 法律问答 Agent：通过 `search_similar_cases` 回答“有没有类似案例”“法院通常如何处理”等问题。

法律问答 Agent 已补充数据库会话兜底逻辑。即使主调用链没有显式传入 PostgreSQL 会话，案例工具也会在本次工具调用期间自行创建并关闭数据库会话。

实际联调中，法律问答 Agent 同时调用了：

- `search_similar_cases`
- `search_statute`

并根据检索结果回答了公司拖欠工资的案例处理方式。
